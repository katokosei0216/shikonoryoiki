# 嗜好の領域：口コミ投稿＆マイページ履歴表示（2026-11-13）

## 対応内容

- 商品詳細ページの星評価（1〜5）＋本文（1〜1000文字）の投稿
- 投稿内容は MySQL `reviews` テーブルに保存されるため、再ログイン後も残る
- 投稿済みの商品では新規追加ではなく更新。自分の口コミだけ削除できる
- 商品詳細には最新5件、拡大表示では口コミ一覧・星数と本文による絞り込み
- マイページの「投稿コメント履歴」で自分の履歴を確認
- 投稿履歴の各商品名から元の商品詳細へ移動し、編集・削除できる
- 商品詳細の「自分の投稿履歴」からマイページへ移動できる
- 既存の黒・ゴールドを基調としたデザインは維持

## 変更ファイル（既存サイトに上書きするもの）

```
html/detail.html
html/mypage.html
js/common.js
js/detail.js
js/mypage.js
css/detail.css
css/mypage.css
php/review.php
```

`php/profile.php` は変更不要です。もともと投稿履歴を返す処理が実装されています。

## 導入手順（既存サイトへ差分ZIPを適用）

1. 先にサイトのファイルとMySQLデータベースをバックアップします。
2. ZIPの `html/`, `js/`, `css/`, `php/` をサイトのルートへ同じディレクトリ構造で上書きします。
   例: サイトの設置先が `/var/www/html/shikonoryo` なら、その中へファイルを上書きします。
3. MySQLに `reviews` テーブルが存在するか確認します（下記のSQL）。
4. テーブルが存在しなければ、付属の `sql/ensure_reviews.sql` をMySQLで実行します。
5. `php/review.php` のデータベース接続設定が、稼働中の `php/login.php` / `php/profile.php` と一致するか確認します。
6. Apache/PHP経由でサイトを開き、ブラウザーで `Ctrl + F5` を押して更新します。

### テーブルの確認

MySQLにログインした状態で:

```sql
USE shikodb;
SHOW TABLES LIKE 'reviews';
DESCRIBE reviews;
```

**注意**: `shikodb.sql` を既存DBにそのまま再インポートしないでください。
`DROP TABLE` が含まれるため、すでに登録したアカウント・お気に入り・口コミなどが消えるおそれがあります。
付属の `sql/ensure_reviews.sql` は、テーブルがないときだけ作成するSQLです。

## 動作確認

1. ユーザーAでログインし、商品詳細で星数を選択、本文を入力して「投稿する」をクリックします。
2. 投稿成功のメッセージと、商品詳細の「みんなの口コミ」に投稿が表示されることを確認します。
3. マイページの「投稿コメント履歴」を開き、同じ商品名・星評価・本文・投稿日が見えることを確認します。
4. 履歴の商品名をクリックして詳細に戻り、本文を変えて「更新する」を押します。マイページでも更新後の本文が表示されることを確認します。
5. 商品詳細で「削除する」を押し、商品詳細とマイページから消えることを確認します。
6. ユーザーBから、ユーザーAの口コミは見られるが編集・削除はできないことを確認します。
7. 空欄投稿、星未選択、1000文字超、未ログインで投稿できないことも確認します。

## エラー時の確認

- 口コミ一覧に「サーバーエラー」が出る場合は、Apache/PHPのエラーログと `reviews` テーブルの有無・DB接続設定を確認します。
- `401` / 「ログインしてください」が出る場合は、PHPセッションが有効か、同じホスト名/IPアドレスでログイン後のページを開いているか確認します。
- `404` の場合は `php/review.php` がサイト内の正しい場所に配置されているか確認します。
- ブラウザーの開発者ツール（F12）のNetworkタブで `php/review.php` の通信結果を確認すると切り分けできます。

## 注意

元のソースに口コミ用APIとマイページの履歴取得APIはすでに存在していました。
今回のパッチは投稿フォームの入力検証、履歴への導線、見やすさ、連続送信・同時投稿時の安全性を改善したものです。
実際のWSL/Apache/MySQLの稼働環境には接続していないため、DBを使った結合動作は現地で確認してください。
